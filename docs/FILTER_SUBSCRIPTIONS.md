# Optional Turan Shield subscriptions

EasyList and EasyPrivacy are optional, disabled by default, and distinct from
the small bundled Turan starter list. Native user consent names the publisher,
HTTPS URL, license and transport before enabling a subscription. Browsing URLs,
cookies, authentication credentials and referrers are not sent. No downloaded
filter lists are redistributed in the application packages.

The native updater uses Windows WinHTTP TLS 1.2 or later and direct DNS. These
requests are outside CEF's browser Secure DNS/proxy settings. This is stated in
the consent dialog; this transport must not be represented as Tor routing or
as browser-wide DNS leak protection. A Tor-only isolated process should leave
this normal-profile optional updater disabled.

Only the compiled official URLs are accepted:

- [EasyList](https://easylist.to/easylist/easylist.txt)
- [EasyPrivacy](https://easylist.to/easylist/easyprivacy.txt)

Redirects, automatic cookies/authentication, compressed responses, non-text
responses and bodies over 5 MiB are refused. The worker enforces network
timeouts and a request budget. A successful list refresh is due after 24 hours;
failure retries after one hour. Native manual refresh is explicit.

Lists must be valid UTF-8 with an Adblock Plus header and fit the parser's line,
rule and compiled-program budgets. Turan implements the bounded ABP subset in
`filter_engine.cpp`. Unsupported constrained rules are skipped whole, rather
than relaxed into broader blocking rules. Scriptlets, executable redirects and
unsupported procedural cosmetics are not executed. The panel reports actual
accepted network/cosmetic counts and skipped unsupported/invalid counts.
Grossly malformed input is rejected before publication. These subscriptions do
not imply full EasyList dialect support.

Profile-owned consent state and per-list caches are separate from legacy
browser metadata. SHA-256 detects cache corruption; it is not a publisher
signature. Windows TLS authenticates the live publisher. Cache writes are
atomic and retain a validated previous version. Invalid current caches are
preserved; a validated backup may be used with an explicit recovery status.
Rollback restores the previous validated list. Failed network, parsing,
publication or path checks retain the active engine. Disabling removes the
list from the next complete policy publication; custom rules and starter rules
remain active. Request counters are generated by actual Shield decisions.

The publisher's [license notice](https://easylist.to/pages/licence.html) offers
GPL version 3 or later, or CC BY-SA 3.0 or later. The native catalog and panel
retain that attribution. User-downloaded caches retain the publisher's text.
Downloaded lists should be handled under their own license when redistributed.

The manager's constructor/cache parsing and complete Shield publication run
off the UI thread. `RefreshAsync` starts one serialized worker. The native
timer schedules automatic refresh only for enabled lists. Closing a panel does
not erase consent or caches. Application shutdown must keep the manager alive
until its bounded worker completes; it must not detach work onto destroyed
profile or Shield objects.

Focused native verification: `python tools/subscription_test.py`. This builds
against the existing native core without changing its build tree. Live HTTPS,
full-list parser, combined policy and restart cache verification:
`artifacts/subscription-native/filter_subscription_tests.exe <source-root> --live`.
Native fixtures use their own temporary profiles and synthetic rule URLs;
normal user profiles are not modified.
